# 整窗破损与碎片生命周期

## 完整界面需要完整渲染源

只移动背景或内容区无法带走标题栏和边框。局部损伤应读取整窗实时画面；完全碎裂则在 frame_post_draw 后捕获整窗快照，把固定 UV 分配到三角碎片。原业务实例与动画纹理分开持有，才能在界面失效后继续播放下落。

## 用真实销毁判断动画起点

queue_free 会延迟到帧尾，仅等待一次 process_frame 不能保证原节点已释放。不同帧时序下，实际 GPU 验收曾发现旧 UI 仍有效。先显示零进度静止网格，等待目标实例失效后才启用运动，可同时满足立即结束交互与连续画面。

带 _process 的脚本在加入场景树时可能自动启用处理，应在 add_child 完成后显式 set_process(false)，防止静止等待阶段提前移动。

## 局部复制必须检查移动后的像素

当前 Forward+ 路径的 BackBufferCopy 矩形模式未正确应用节点变换，移动窗口后右侧和底部会出现未初始化黑色区域。全视口复制加窗口采样边界夹限解决了实际渲染问题；无损时关闭复制，避免常驻开销。仅验证窗口矩形或裂纹存在不能发现此问题，应对画面异常黑色区域和快照首帧做像素检查。

## 实例身份与隔离验证

异步完成回调应携带原实例标识，防止关闭重新打开的同 ID 应用。冻结要覆盖 ALWAYS 子节点和焦点，API 还须保留学习、导入和剧情保护。24 项窗口 GUT、170 项特效 GPU 检查和 150 项完整桌面回归通过，证据保存在 docs/scenes/desktop_review/window_lab。
