# 会话内时间与闪卡调度

- 统一时钟必须贯通业务层、SQL 的 `last_review_time` 和历史 JSON。只替换 Manager 的当前时间会被数据层重新读取真实时间覆盖。
- 调时只保存内存偏移，正常评分照常持久化；用两个独立进程验证启动重置和数据库保留，避免仅以新建对象代替重启证明。
- 学习卡的 due 必须使用秒级时间戳。已有调度分支曾写入天索引，与查询及实体约定不一致；分钟级到期测试能发现这一问题。
- 学习中刷新队列时保留当前实体、翻面和单调计时，只刷新后续卡片；累计接纳 ID 保证重复到期不重复消耗额度。读取失败须同时阻止按钮和业务评分入口。
- 日期先自行校验月份天数和闰年，再调用 Godot 时间转换，否则非法日期会触发引擎错误，而不只是业务验证失败。
- 间隔文案从同一次调度结果生成；再次计算可能因为 FSRS 随机模糊化得到不同的间隔。
- GPU 验收中的点击目标必须可见；复用最小窗体会把快捷按钮放到滚动区外，需要展开后再点击，并断言软件时间确实前进。
- JSON 快照使用完整浮点精度，读取后恢复实体类型，再比较跨进程数据，避免 JSON 数字类型和精度造成误判。
- 隔离基线为 127 项中 120 项通过、7 项原有失败；完成后为 147 项中 140 项通过、同一组 7 项失败。新增 20 项及 211 条断言、119 项 GPU 检查、12 项跨进程检查通过。
