# 文件维护目录整理

## 维护边界

内容放入 `content/`，实现放入 `src/`，自有场景和 GDScript 分离。测试也用 `tests/scenes/` 与 `tests/scripts/` 分开，GUT 继续使用 `tests/unit/`。插件遵循插件自己的布局，`content/scenes/system/` 明确作为 AI 维护的装配场景。

## 引用与存档

不能仅移动文件并依赖 UID。场景外部资源、预加载、对白动作、工作流和 `.import` 的源路径都要同步。保存下来的剧情、教程资源没有脚本 UID；使用临时副本转换引用，再加载到内存，才能保留原存档和已有备份。壁纸存档中的选择与解锁列表也需要兼容素材路径。

资源加载工具要保留调用方的缓存模式，尤其备份恢复使用 `CACHE_MODE_IGNORE`，避免读档时刷新其他持有同一资源的对象。

## 既有修改与验证

整理前记录工作区原文件和 Git 索引，移动时携带已有修改。提交目录变动时以原索引内容生成迁移内容，保留用户原有的未提交修改。

整理前后完整 GUT 失败集合一致：原来 123 项中 116 项通过；整理后 127 项中 120 项通过，仍为“我的电脑”的 7 项既有失败。全部 39 个场景、78 个实现脚本加载通过，241 条资源引用有效，摄像头 Forward+ 真实渲染 17 项通过。

Godot 4.7.2、插件和实际验证结果应分别记录；导入进程成功退出不能代表插件编辑器诊断全部消失。
