### 2.3 Autoload 注册方案（推荐）

**项目设置 → 自动加载**：

| 单例名   | 路径                 | 说明                 |
| ----- | ------------------ | ------------------ |
| `App` | `res://src/app.gd` | 唯一 Autoload，全局访问入口 |

`App.gd` 的职责：

- 在 `_ready()` 中按顺序实例化 DB → Manager
- 建立依赖注入链：`deck_db` → `deck_manager`（`set_db_manager()`）
- 对外提供只读访问：`get_deck_manager()`、`get_study_manager()` 等
- 全局信号转发（可选）：将各 Manager 的 `entity_created` 等信号聚合后暴露

```gdscript
# App.gd（Autoload 单例）
extends Node

# 数据层（运行时实例化）
var _deck_db: DeckDB
var _note_db: NoteDB
var _card_db: CardDB

# 逻辑层（运行时实例化）
var _deck_manager: DeckManager
var _note_manager: NoteManager
var _card_manager: CardManager
var _study_manager: StudyManager

func _ready():
    # 1. 初始化数据层
    _deck_db = DeckDB.new(); _deck_db.name = "DeckDB"; add_child(_deck_db)
    _note_db = NoteDB.new(); _note_db.name = "NoteDB"; add_child(_note_db)
    _card_db = CardDB.new(); _card_db.name = "CardDB"; add_child(_card_db)
    # ... 打开数据库、初始化 schema ...

    # 2. 初始化逻辑层
    _deck_manager = DeckManager.new(); add_child(_deck_manager)
    _note_manager = NoteManager.new(); add_child(_note_manager)
    _card_manager = CardManager.new(); add_child(_card_manager)
    _study_manager = StudyManager.new(); add_child(_study_manager)

    # 3. 注入数据层引用（依赖注入）
    _deck_manager.set_db_manager(_deck_db)
    _note_manager.set_db_manager(_note_db)
    _card_manager.set_db_manager(_card_db)
    _study_manager.set_db_manager(_card_db)  # StudyManager 主要透传 CardDB
    # 可选：StudyManager 内部持有 CardManager 引用

    # 4. 连接跨 Manager 信号（可选）
    _note_manager.entity_created.connect(_on_note_created)

# 对外只读访问
func get_deck_manager() -> DeckManager: return _deck_manager
func get_study_manager() -> StudyManager: return _study_manager
func get_note_manager() -> NoteManager: return _note_manager
func get_card_manager() -> CardManager: return _card_manager
```

### 2.4 UI 层如何访问 Manager

```gdscript
# UI 层脚本示例（如 deck_list.gd）
```

### 2.6 各层节点归属规则速查

| 层级       | 继承自                  | 节点树归属                  | 生命周期                 |
| -------- | -------------------- | ---------------------- | -------------------- |
| **UI 层** | `Control` / `Node2D` | `root/Viewport` 下的场景实例 | 随场景切换创建/销毁           |
| **逻辑层**  | `Manager` → `Node`   | `App` 子节点              | 全局持久，应用启动到关闭         |
| **数据层**  | `DBManager` → `Node` | `App` 子节点              | 全局持久，数据库连接保持         |
| **实体层**  | `RefCounted`         | **不加入节点树**             | 由调用方持有引用，引用计数归零时释放   |
| **调度层**  | `RefCounted`         | **不加入节点树**             | 由 Manager 临时实例化，用完释放 |

## 四、调度层接口（Scheduler） —— 新增解耦层

> 设计目标：算法与持久化彻底分离。Scheduler 只负责**状态机计算**，不负责**保存状态**。

### 4.1 Scheduler 基类（抽象接口）

```gdscript
class_name Scheduler
extends RefCounted

# 评分枚举
enum Rating { AGAIN = 1, HARD = 2, GOOD = 3, EASY = 4 }

# 队列类型
enum Queue { NEW = 0, LEARNING = 1, REVIEW = 2, SUSPENDED = -1, BURIED = -2 }

# ── 核心算法接口 ──

## 计算下一次复习状态（纯函数，无副作用）
## 输入：当前 CardEntity + 用户评分
## 输出：新的状态字典（不修改原始 CardEntity）
func calculate_next_state(card: CardEntity, rating: int, now_timestamp: int) -> Dictionary
    # return {
    #   "queue": int,
    #   "due": int,
    #   "reps": int,
    #   "lapses": int,
    #   "stability": float,
    #   "difficulty": float,
    #   "interval_days": int     # 仅用于展示/调试
    # }

## 获取卡片当前应归属的队列（用于初始化/恢复）
func classify_queue(card: CardEntity, now_day_index: int, now_timestamp: int) -> int

## 初始化新卡片的默认调度参数
func get_initial_state() -> Dictionary

# ── 学习进度估算 ──

## 估算某评分对应的下次间隔（用于按钮上展示"4天后"）
func estimate_next_interval(card: CardEntity, rating: int) -> String
```
