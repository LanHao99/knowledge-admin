# 第一章：记忆校勘交互草案

日期：2026-10-19。整理：Codex / OpenAI。

状态：已确认情感目标、探索方向、跨应用操作手感与 MIRA 的内部线人定位；正在讨论组合谜题与设计支柱，尚未锁定实现范围。

## 作者已确认的方向

- 希望玩家获得「好奇与共谋」的感受：和 MIRA 一起读懂并绕过系统规则。
- 选择「记忆校勘员」：发现矛盾、保存证据、绕过规则。
- 核心手感选择「跨应用协作」：在卡片、文档和窗口间组合线索。
- MIRA 定位为「可靠的内部线人」：了解部分规则，但需要玩家在桌面动手。
- 第一章前面的剧情可以重写，现有情节、台词和事件顺序不作为硬约束。
- 上一条仅明确指第一章，不把它自动扩展为全部章节或世界设定的取舍。

本文基于这些确认继续设计。其他机制均为待讨论提案。案例依据与工程检查见 [Meta 调研](meta_interaction_research.md)。

## 第一章要完成的体验

玩家从「正常使用一台电脑」进入「与可靠的内部线人共同处理异常」。通过一次跨应用行动，玩家确认：卡片中的规则、文档中的证据和 MIRA 的内部信息能够相互校验；自己能在桌面上完成她无法执行的操作。

章末关系的目标是成为愿意继续合作的伙伴。MIRA 的来历、意识性质和系统的最终立场可以继续保留疑问，开场不需要先用长段对白作出解释。

暂定电梯提案：**MIRA 能看到内部编号，却无法读取你的文档；你从卡片学到记录规则，在桌面找出正确来源，把系统流程之外的证据留了下来。**

## 第一条规则：报告有范围

### 异常

一次整理后，系统报告「本次任务留存记录：0」，但玩家保存在个人记录里的文字仍然存在。

这个差异最初像故障。点开任务详情后，可以核对到：此次任务只处理并统计「临时记录」。个人记录不属于它的范围。因此，零条记录是真实的局部结果，不能被当作所有地方都没有记录的证明。

### 规则与因果

- 临时记录会在玩家确认执行整理时清除。
- 个人记录只有明确保存后才能跨次打开保留。
- 整理任务只统计临时记录，任务范围从第一次展示起就可查看。
- 复制文字不会停止原件被整理，却能在其他位置留下证据。

这些是本草案提出的虚构软件规则，不是现有功能的描述。首个原型可以用两个清楚标明用途的文档承载，不必先建设完整目录、权限和删除系统。

### 玩家为什么需要自己操作

系统界面只提供完成当前整理任务的操作；玩家要自行意识到，可以先离开这个流程，在普通文档编辑器里留下副本，再回来执行整理。

第一次越界发生在「系统给出的任务步骤」与「玩家能操作的整张桌面」之间。玩家拥有比当前任务界面更广的行动空间。

## 教学小实验：报告有范围

| 环节 | 玩家可观察的事实 | 玩家行动 | 可验证的后果 |
| --- | --- | --- | --- |
| 建立常识 | 普通个人记录区分草稿与已保存状态 | 保存一句无关紧要的测试文字，关闭重开 | 文字仍在，证明保存机制可靠。 |
| 出现问题 | 临时记录里出现一段值得保留的消息；整理任务列明处理范围 | 检查消息、任务详情和个人记录 | 三处材料共同给出完整规则，没有一个界面直接给答案。 |
| 提出假说 | 临时记录与个人记录是不同范围 | 预测复制后再整理会发生什么 | 玩家能在行动前说出「原件消失，副本保留」。 |
| 绕过流程 | 当前任务没有「保留这段消息」按钮，但桌面仍有普通编辑器 | 把消息复制到个人记录并保存，然后执行整理 | 临时原件消失；任务报告为零；个人记录仍在。 |
| 共同确认 | MIRA 对其所见结果作出回应 | 向她展示或说明留下的证据 | 她的回应承接玩家实际保存的状态，双方确认同一条规则。 |
| 迁移 | 另一段临时内容出现 | 不依赖完整提示再次保留所需片段 | 检查玩家掌握的是规则，而非一次点击顺序。 |

消息的具体内容待定，应能引起好奇并在后续成为有意义的证据。解题本身不依赖玩家猜出 MIRA 的身份，也不要求复用旧第一章的情感经历。

## 组合谜题：同名的两封信

这是依据已选操作手感提出的首个组合谜题。它把上面的保存实验扩展到三个应用，不要求先建设完整虚拟文件系统。

### 应用与窗口的分工

| 载体 | 独有的信息或能力 | 玩家从这里带走什么 |
| --- | --- | --- |
| Knowledge Admin 的作者示例卡 | 提供可迁移的引用规则：文件名是标签，核对记录需结合来源与接收编号 | 一种判断两份记录是否对应同一来源的方法。 |
| 我的电脑 | 提供两份同名记录的实际正文、来源与编号，并允许保存个人记录 | 具体证据，以及带来源的持久副本。 |
| 未知程序中的 MIRA 协作页 | 展示当前接收批次与内部编号；MIRA 解释她能确认的内部状态，并接收玩家主动提交的证据 | 本次调查的定位条件，以及对操作结果的内部复核。 |
| 桌面窗口管理 | 支持并排、切换与最小化，保留应用现场；关闭意味着结束当前窗口会话 | 一套能同时使用不同工具的工作方式。 |

首章卡片使用作者提供的示例材料，不要求修改玩家自己的知识题目。来源字段是可阅读、可选择的记录信息，不把随机编号变成需要手打的密码。

### 具体流程

| 环节 | 呈现 | 玩家需要完成的连接 |
| --- | --- | --- |
| 接收内部线索 | MIRA 能确认当前任务关联的记录为 R-17，并说明索引中存在同名旧缓存；她无法读取外部文档正文 | 明白内部编号能缩小范围，但还不能代替查阅文档。 |
| 学习引用规则 | 示例卡说明怎样以来源和接收编号核对一条记录 | 从「找相同标题」转为「核对它来自哪次接收」。 |
| 跨窗口调查 | 保留通信现场，在我的电脑中查看两份同名材料；旧缓存标 R-09，本次材料标 R-17，来源字段也可核对 | 将卡片方法、内部条件与实际文档合并，确定本次需要保留的对象。 |
| 形成证据 | 将选定正文及来源信息存入个人记录，并明确保存 | 把一次阅读转为一份之后仍能复核的证据。 |
| 交回证据 | 回到通信页，主动提交已保存的引用 | MIRA 通过提交渠道核对对应记录，而非自动窥见编辑器里的所有输入。 |
| 检验保存规则 | 玩家确认执行整理；临时记录归零，已保存副本保留 | 在外部文档和内部报告之间确认结果，完成首次规则利用。 |

两份记录的具体正文等待后续写作。首章可以先保存一次有意义的通信结果，让这份证据既服务当前推理，也成为双方第一次合作留下的物件。

### 成功判定与反馈

- 判定依据是保存成功、正文与来源对应、提交的是本次所需记录；不按固定的应用访问顺序判定。
- 理解引用规则的玩家可以直接应用，不用为了开锁重复翻阅教学卡。
- 仅复制正文而未保留来源时，MIRA 可以指出无法区分两条同名记录，提示缺的是哪类证据。
- 提交旧缓存时，她可根据可信的内部编号说明记录不属于本次任务，不以含糊的「错误答案」结束反馈。
- 并排摆放、任务栏切换或最小化都可完成协作，不强制「必须最小化一次」或精确对齐窗口。
- 关闭通信窗口后可以重新连接继续。保存在文档里的证据不因连接结束消失；确需重建的临时会话状态应明确说明。

## 玩家与 MIRA 的信息分工

已选定位：可靠的内部线人。第一章中，她对自己掌握的机制事实提供可靠信息，知道的内容与能操作的对象都有明确边界。

| 分工 | MIRA | 玩家 |
| --- | --- | --- |
| 可见的信息 | 当前内部任务、接收编号及她有权限查看的状态 | 卡面、外部文档、桌面布局与保存结果。 |
| 能执行的操作 | 通过通信页提供事实、接收主动提交的证据、复核对应关系 | 切换应用、比较、选择来源、保存与提交。 |
| 信息边界 | 未收到提交时不自动知道个人记录内容；未知之处明确说明 | 不能只凭外部界面直接知道全部内部原因。 |
| 悬念所在 | 她为什么拥有这些权限，以及这些规则由谁设定 | 通过后续证据逐步理解系统与她的关系。 |

提示按层递进：先指出缺少哪类信息，再提醒某个工具的用途，最后才提供具体操作。玩家可主动请求更多提示。她默认提供内部条件与约束，把跨应用连接和关键操作留给玩家。

## 已选手感：跨应用协作

每个谜题设计为一条信息流：从一个应用取得方法或线索，在另一个应用中应用，再把带来源的结果交给需要它的一方。比对与小实验服务这条信息流，谜题允许合理的不同操作顺序。

跨应用协作的满足来自信息终于接上、工具在新情境下发挥作用，以及 MIRA 复核了具体结果。切换界面本身不作为难度；每次转移都应带着新信息、需要使用的能力或可提交的证据。

## 循环与节奏

| 尺度 | 循环 | 玩家的主要选择 |
| --- | --- | --- |
| 约 30 秒 | 取得线索 → 在另一工具中应用 → 看见局部反馈 | 这条信息能用在哪个应用里。 |
| 约 5 分钟 | MIRA 提供内部条件 → 卡片提供方法 → 文档形成证据 → 交回并复核 | 如何组合来源、保留什么，以及下一步需要哪个工具。 |
| 第一章 | 建立工具用途 → 完成首次跨应用合作 → 独立迁移规则 → 留下下一章疑问 | 决定愿意和她继续调查什么。 |
| 跨章节 | 学到规则 → 发现适用边界 → 用组合规则解决新问题 | 逐渐形成自己的调查方法。 |

普通复习仍提供熟悉感与日常节奏。首章原型使用作者提供的材料，不以真实学习失误触发不可逆后果，也不把旧稿中「Again 伤害 MIRA」作为前提。

## 动机与操作反馈

- 自主性来自玩家选择工具与处理顺序，并负责最后的提交。
- 胜任感来自跨应用信息能被正确关联，同一规则能在新对象上再次成立。
- 关系感来自 MIRA 提供可靠的内部事实，而玩家完成她权限之外的部分；回应承接具体帮助。
- 保存、整理和重新打开需要各自明确的视觉与声音反馈；结果从实际状态得出，避免对白宣布成功而文件仍不一致。

## 原型边界与工程约束

- 目标体验约 10～15 分钟，只验证一个谜题闭环，不把它当作第一章总长度或工期承诺。
- 范围为 Knowledge Admin、我的电脑与未知程序三个应用，共用现有窗口管理。材料限制在最多两张作者示例卡、两份待核对记录和一份个人记录，暂不依赖新增回收站和文件改名。
- 当前正式对话禁用其他桌面应用，结束时会释放未知程序。要维持协作现场，需要新增可在探索期间普通切换的通信页，或等价的返回通信入口；不能把现有模态对白当成已经支持跨应用协作的界面。
- 普通通信页的持续存在不等于持续占用剧情模态；正式对白、探索阶段和证据提交需要明确转换。
- 需要补充来源信息、保存成功事件、提交与复核、任务状态、整理后的内容状态及重复触发保护；这些能力尚未实现。
- 探索没有真实倒计时。整理由玩家明确执行，玩家可以暂停、关闭重开并继续，不因猜错而失去唯一证据。
- 仅输入未保存时，重开应给出与教学一致的结果；保存失败时不推进任务。任何重试都需要保留可观察的原因与继续路径。

## 应观察的试玩证据

- 玩家能否解释卡片、文档和 MIRA 各自提供了什么。
- 面对同名记录时，能否主动用来源与接收编号核对。
- 保存与提交前，能否预测原件、副本及内部报告各自的结果。
- 不按示范点击顺序、改用并排或任务栏切换时，是否仍能完成任务。
- 能否在迁移环节再次应用规则，而无需相同提示。
- 能否记得 MIRA 提供了什么，自己又提供了什么，而非只记得一次文件操作。

## 下一步讨论

核心操作手感与 MIRA 定位已经确定。下一步确认下列设计支柱，再确定线索呈现顺序、消息正文、失败反馈和章末疑问。谜题方案及原型范围仍是讨论稿。

## 待确认的设计支柱

| 支柱 | 定义 | 决策检验 |
| --- | --- | --- |
| 应用各有用途 | 每个应用提供不同的信息或能力，组合后才能形成完整处理方式 | 若三个应用只是重复展示同一条线索，应合并或重新分工。 |
| 熟悉操作可以被巧用 | 保存、关闭和引用等基础行为保持可靠，异常与利用方式可以追溯原因 | 在随机改变按钮含义与可推导的规则组合之间，选择后者。 |
| MIRA 可靠但受限 | 第一章里，她掌握的机制事实可信，知识与权限有清楚边界 | 需要悬念时，从未知来源、缺少权限或不完整背景展开，不临时让她谎报机制事实。 |
| 关键连接由玩家完成 | MIRA 提供内部条件，玩家完成跨应用连接与关键操作 | 在默认给出逐步点击答案与保留推理空间之间，优先后者，并提供主动求助。 |

支柱之间的张力：可靠的线人需要足够有用，同时保留玩家的发现空间；熟悉的工具保持稳定，同时允许组合出令人意外的用途。设计时需要同时满足两端。

### 对应边界

- 不靠无关密码凑谜题，避免削弱应用之间的功能分工。
- 不用隐藏点击顺序或强制访问次数判定成功，避免把玩家理解替换为流程记忆。
- 不把真实学习笔记的损坏当作剧情代价，保留日常工具的可信度。
- 第一章不以反复猜测 MIRA 是否在谎报规则作为主要难度，保持已选择的可靠内线定位。

这些支柱及边界尚待作者确认。当前 review mode 为 lean；本阶段不进行 CD-PILLARS 与 AD-CONCEPT-VISUAL 的代理评审，也不据此生成已定稿的游戏概念。
