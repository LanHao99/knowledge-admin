### Decks

由笔记中的deck_id确认

```sql
-- 1) 卡组表（核心）
CREATE TABLE IF NOT EXISTS decks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,                         -- 卡组名，如“日语/N5/动词”
    parent_id INTEGER DEFAULT NULL,             -- 父卡组（支持树形/子卡组）
    sort_order INTEGER NOT NULL DEFAULT 0,      -- 同级排序
    is_archived INTEGER NOT NULL DEFAULT 0,     -- 0=正常 1=归档
    created_at INTEGER NOT NULL,                -- 创建时间戳
    updated_at INTEGER NOT NULL,                -- 更新时间戳

    FOREIGN KEY(parent_id) REFERENCES decks(id) ON DELETE CASCADE
);

-- 防止同一父级下重名（根节点 parent_id 为 NULL 时可按业务再处理）
CREATE UNIQUE INDEX IF NOT EXISTS idx_decks_parent_name
ON decks(parent_id, name);

-- 2) 卡组配置（可选，但推荐，便于“每个卡组不同学习策略”）
CREATE TABLE IF NOT EXISTS deck_configs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,                         -- 配置名，如“默认配置”
    new_limit_per_day INTEGER NOT NULL DEFAULT 20,
    review_limit_per_day INTEGER NOT NULL DEFAULT 200,
    learning_steps_json TEXT NOT NULL DEFAULT '[10,1440]', -- 分钟
    graduating_interval INTEGER NOT NULL DEFAULT 1,         -- 天
    easy_interval INTEGER NOT NULL DEFAULT 4,               -- 天
    created_at INTEGER NOT NULL
);

-- 3) deck 绑定配置（一个 deck 用一个配置）
ALTER TABLE decks ADD COLUMN config_id INTEGER REFERENCES deck_configs(id);

-- 4) 在 cards 里挂 deck_id（关键）
-- 你已有 cards 表的话，加这一列即可：
-- ALTER TABLE cards ADD COLUMN deck_id INTEGER NOT NULL REFERENCES decks(id) ON DELETE CASCADE;
-- 再加常用索引：
CREATE INDEX IF NOT EXISTS idx_cards_deck_queue_due ON cards(deck_id, queue, due);
```

### Notes

同一个知识点可能需要多张单元化的卡片来进行测试，如果仅仅使用离散的卡片进行存储的话，若要对知识点进行修改，则需要单独对每张卡片进行编辑。为此anki将知识点保存为笔记，然后每一张复习的卡片则是提取笔记中的字段

像note这种纯数据的东西，它是不需要设计一个godot里面的class的，因为class主要的目的还是进行节点的集成，它只是一种静态的存储数据的一种结构，那就直接封装为调用读取函数和一个数据表就行

```sql
CREATE TABLE IF NOT EXISTS notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    note_type_id INTEGER NOT NULL,        -- 告诉系统这条笔记用的是哪个模板
    fields_data TEXT NOT NULL,            -- 这里用 JSON 存所有的卡片变量内容
    deck_id INTEGER NOT NULL,
    created_at INTEGER
);
```

AUTOINCREMENT：自动递增，程序会自动维护一个计数器，保证 ID 的唯一性

#### 自定义字段 fields_data

Anki里面是把字段和卡片这两个东西解耦的，卡片规范了一个卡片长什么样，写的是HTML和CSS代码，而字段则是规定了卡片中呈现什么。这个地方我们先还原自定义字段。

```json
{
  "id": 1,
  "name": "日语综合模板",
  "fields": [
    {"name": "Word", "description": "单词本体"},
    {"name": "Kana", "description": "假名发音"},
    {"name": "Sentence", "description": "例句"},
    {"name": "Grammar", "description": "语法解析"}
  ],
  "templates": []
}
```

在这里用fields来保存字段，用templates保存模板，当用户创建新卡片时，他应该调用如下两句：

```json
{
note_type_id = 1
fields_data = '{"Word": "林檎", "Kana": "りんご", "Sentence": "これは林檎です。", "Grammar": "名词"}'
}
```

而模板字段在cards界面由template_order​调用

### Cards

```sql
CREATE TABLE IF NOT EXISTS cards (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    note_id INTEGER NOT NULL,             -- 关联到 notes 表的 id
    deck_id INTEGER NOT NULL,             -- 所属卡组
    template_order INTEGER NOT NULL DEFAULT 0, -- 模板序号

    -- 基础状态
    queue INTEGER NOT NULL DEFAULT 0,     -- 当前队列：0=新卡片, 1=学习中, 2=复习中
    due INTEGER NOT NULL,                 -- 下次到期时间（时间戳）
    reps INTEGER NOT NULL DEFAULT 0,      -- 总复习次数
    lapses INTEGER NOT NULL DEFAULT 0,    -- 遗忘次数(选错的次数)

    -- 复习记录（原 revlogs 合并进 cards）
    last_review_time INTEGER NOT NULL DEFAULT 0, -- 最近一次复习时间戳
    last_rating INTEGER NOT NULL DEFAULT 0,      -- 最近一次评分：1=Again, 2=Hard, 3=Good, 4=Easy
    last_time_taken INTEGER NOT NULL DEFAULT 0,  -- 最近一次作答耗时(ms)
    review_history_json TEXT NOT NULL DEFAULT '[]', -- 历史记录 JSON 数组

    -- FSRS 算法专用字段 (替代老旧的SM-2的ease_factor)
    stability REAL NOT NULL DEFAULT 0.0,  -- 记忆稳定性 (S)
    difficulty REAL NOT NULL DEFAULT 0.0, -- 记忆困难度 (D)
    step INTEGER DEFAULT NULL,            -- FSRS 步进索引（NULL=Review已毕业）

    FOREIGN KEY(note_id) REFERENCES notes(id) ON DELETE CASCADE
);
```

##### 数据表关联删除

- ​FOREIGN KEY(note_id) REFERENCES notes(id)​ (外键约束)：对于当前表中的数据note_id，先确认笔记当中有没有对应的ID，然后再进行添加
- ​ON DELETE CASCADE​ (级联删除)：实现删除笔记时，同时删除卡片
