# 剧情测试台

## 布局与操作

在控制面板开启调试模式后，从桌面或开始菜单打开。窗口默认为 1100×760，沿用 Classic95 主题与全局字号。

顶部摘要横向显示章节、进度／阈值和好感度，下一行显示下一段剧情和播放状态。空间不足时摘要自动换行。

- 剧情控制：开启下一段，或按章节筛选后跳转。每条剧情分别显示标题、类型、完成状态与前置条件；前置使用中文剧情标题。跳转按钮的提示说明重排完成记录并保留好感度、分支标记。
- 存档编辑：分为数值、完成记录和剧情标记三个子页。完成记录按章节分组并自动调整列数；标记名与类型、值分行排列。只读派生标记默认收起，复杂值保留只读展示。
- 备份：备份列表与当前存档原文分别展示。列表显示 UTC 时间和备份来源，完整路径通过悬停提示查看。恢复需要先选中备份；重置与恢复保持游戏内确认。

保存、撤销和状态提示固定在底部，不随编辑页滚动。存在草稿冲突时禁用保存并提示重新读取；尚未选择备份或存在未保存修改时禁用恢复。

## 编辑场景

固定结构位于 `res://scenes/desktop/story_test_bench.tscn`，可直接在 Godot 的 2D 编辑器里调整。脚本只填充剧情行、完成记录和标记编辑器，并通过 App 读取或提交数据。

关键节点为 Summary、MainTabs、EditorTabs、BackupTabs 和 DraftFooter。数值与完成记录复用已有自适应网格；滚动容器启用键盘焦点跟随并关闭横向滚动。固定短标签不启用自动换行，避免容器按零最小宽度把文字排成竖列。

## 验证

在独立的 KnowledgeAdminDesktopVerification 工程和存档目录运行 `tests/desktop/verify_story_test.tscn`。追加 `-- --story-layout-only` 可单独运行布局与编辑交互检查；默认还检查剧情播放、停止、自然结束、退出指令和学习现场恢复。

布局矩阵包含 1280×720、1920×1080 的 100%／150% 字号，以及 720×500 最小窗口的 150% 字号。检查六个页面的真实画面、横向约束、滚动区可用高度和保存按钮可见性，同时实际点击保存与撤销，验证章节筛选和只读展开不改变草稿。

自动推进另由 `test_story_auto_advance.gd` 验证：只有 `{auto}` 的空白行仍应推进，禁用文字动画仍保留推进语义，普通空白行不触发推进。

截图与验收报告位于 [布局验收目录](desktop_review/story_test_layout/)。

Godot 4.7.2 下，完整单元测试 85 项、566 条断言通过；GPU 验收 265 项检查通过，包含完整剧情播放回归及五组窗口／字号组合的六个页面。运行使用独立工程和存档，未写入正式玩家存档。环境仍输出系统证书及已有退出资源提示，断言和进程退出状态均通过。
