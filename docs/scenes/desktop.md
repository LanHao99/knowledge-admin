# Classic98 桌面系统

## 启动与应用

主入口为 boot_screen.tscn；全屏波浪与文字停留约 1.6 秒，再从中心向外溶解 1.4 秒露出桌面。鼠标或按键将剩余转场加速至最多约 0.6 秒。桌面不自动打开闪卡。双击或键盘确认快捷方式可启动应用；开始菜单单击启动。所有应用采用单实例。

启动封面使用深蓝／青紫液态波浪，中央显示“正在启动系统”。原生文字与波浪置于同一个 CanvasGroup，用统一噪声遮罩从中心向外溶解。独立 CanvasLayer 跨过启动入口的场景切换，桌面提前在下层初始化，准备完成后才允许揭开封面；转场期间输入被拦截，结束后恢复桌面处理并释放封面。时长、着色器参数与动画预览见 [启动封面](boot_screen.md)。

WindowManager 注册 knowledge_admin、ai_cards、control_panel、my_computer、recycle_bin、camera、window_lab、unknown_program、help。后两者没有桌面或开始菜单入口。我的电脑提供预设目录和可编辑文档，修改写入 `user://my_computer_documents.cfg`；回收站是空内容演示。两者都不读写真实磁盘目录。

“窗口实验室”在桌面和开始菜单提供入口，包含“完全破碎窗口”“不完全破损”“恢复”三个按钮。局部裂纹保留实时交互；完全破碎先结束应用，再由独立桌面特效显示包含标题栏、边框和 UI 的快照碎片。使用方法、Inspector 参数和验收见 [窗口实验室](window_lab.md)。

“摄像头”在桌面和开始菜单提供入口，默认 560×560，显示 MIRA 的透明背景人物头像。普通缩放与最大化均保持整窗方形，复用现有拖动、最小化和任务栏行为。内容根节点通过 `@export` 暴露立绘、缩放、偏移、镜像、背景色及 CRT 参数，支持编辑器预览。CRT 只处理自己的画面，不采样桌面；详细参数及渲染证据见 [摄像头窗口](camera.md)。

## 我的电脑预设文件

目录说明及虚拟 txt 正文统一保存在 `res://data/desktop/my_computer_files.tres`，由 `my_computer.tscn` 根节点的 `file_catalog` 属性引用。

在 Godot Inspector 打开该资源：`drive_description` 与 `programs_description` 分别编辑系统盘和程序目录说明；`documents` 数组保存文档。展开每个 DesktopTextFile 资源，用 `file_name` 修改文件名，用多行 `content` 编辑正文。运行应用时按数组生成目录，因此新增、删除或改名条目无需修改查看器脚本。

两个资源类型位于 `data/resources/desktop_file_catalog.gd` 与 `desktop_text_file.gd`；预设正文保存在这一个 `.tres` 中，两个 txt 为内嵌子资源。原有“使用说明.txt”“学习指南.txt”的内容保持一致。在 Inspector 中编辑并保存资源后，重新运行游戏即可看到预设变化。

游戏内选中文档后可以直接修改正文。系统盘和程序目录仍只显示说明，正文使用不透明深灰，避免只读状态落到引擎默认的半透明浅色上。目录项悬浮时保持黑字，名称提示使用不透明浅黄底。切换文件不会询问，草稿留在当前窗口里，未保存的文件名末尾显示 `*`。`Ctrl+S` 只保存当前文档。关闭「我的电脑」，或从开始菜单关闭系统时，只要还有未保存文档，就询问保存、不保存或取消。保存失败时不关闭、不退出。剧情调用的 `App.quit_app()` 不插入这个询问。

覆盖档按文件名保存。正文改回预设内容后，对应覆盖项会删除，之后仍跟随 `.tres`。这份覆盖档不是玩家电脑上的真实 txt。

`tests/unit/test_desktop_file_catalog.gd` 验证默认场景的资源绑定、新增文档生成目录、多行正文显示、未绑定资源时的容错，以及编辑、快捷键保存、覆盖项删除和关闭询问。

## 壁纸

桌面底色仍是青绿色。选择壁纸后，底色之上的全屏图层显示 `res://assets/wallpapers/` 中的图片。铺满时保持比例并裁切边缘；原比例时图片居中，周围是黑边。控制面板的「壁纸」页可以预览和切换，配置保存在 `user://wallpaper_settings.cfg`。未选择壁纸时不显示这一层。

## 窗口与布局

ManagedWindow 的标题栏、内容区、边框及八个缩放把手均保存在场景中。标题栏拖动、八向缩放、双击最大化、最小化、关闭与任务栏切换共用状态。最大化只使用工作区，任务栏高度只扣除一次。

在 desktop.tscn 根节点 Inspector 调整 taskbar_height 和 application_sizes；在 managed_window.tscn 根节点调整 min_window_size。默认位置大小只在本次运行记忆。字体倍率沿用 UiSettings，标题栏和按钮同步缩放。小窗口、大字号时通过内容滚动访问页面。

最小化保留页面实例。学习中关闭需确认并调用 end_session；正在执行导入事务时不允许关闭。关闭系统有确认和取消。

任务栏的程序入口使用方形图标按钮，复用应用注册表中的图标，不显示程序名称文字。悬停提示和无障碍名称保留完整标题，当前应用保持按下高亮；点击仍然激活、最小化或恢复对应窗口。按钮填满任务栏可用高度并保持方形，图标占按钮边长的 90%，仅保留边框间隙；按钮基础边长为 40 像素，对应图标基准为 36 像素。字体倍率或任务栏高度变化时自动适配，在大字号切回小字号时也会缩回。可在任务栏 Inspector 中调整 app_button_size（基础最小边长）与 app_icon_size（对应基础图标边长），按钮外观保存在 taskbar_app_button.tscn。

## 页面接入

App.open_app(app_id) 返回 bool；App.close_app(app_id) 请求关闭应用。App.goto_scene(path) 保留错误码返回：闪卡页面始终导航到 knowledge_admin，AI 和设置分别打开独立应用，不依赖哪个窗口当前激活。WindowContext 保留单独运行页面时的兼容路径。

恢复焦点时调用可选的 desktop_refresh：主页刷新统计，牌组和笔记仅在未编辑时刷新；进行中的学习和输入表单不重载。

## 剧情与教程

App.request_dialogue(resource, key, track_story=true, source=null) 接受串行请求。正式剧情先于未开始的教程；同类型按请求顺序处理。TutorialManager 传递来源节点，已销毁页面的待播教程丢弃并允许下次重新请求。

StoryDialogueOverlay 现在是可复用 Control，继续使用 DialogueManager 与 TextAnimationController。正式剧情装入未知程序；教程装入使用帮助，且只锁住来源应用。完成后沿用 dialogue_opened / dialogue_closed 通知学习场景。

剧情窗口可以拖动、缩放、最大化，但不能关闭或最小化。模态遮罩、背景处理禁用与焦点禁用共同隔离输入。已有非菜单弹窗暂存隐藏；异步新弹窗也被拦截。完成后恢复原窗口、弹窗和学习现场，未知程序最小化到任务栏。待机窗口关闭只隐藏，不销毁；后续剧情复用同一实例。Esc 只能加速打字，不能跳过选项或完成剧情。

## 剧情测试台

调试模式开启后，桌面和开始菜单出现「剧情测试台」。关闭调试模式时窗口关闭，入口隐藏。它使用现有单实例窗口，默认为 1100×760，可拖动、缩放和最小化。页面放在滚动容器里，字号跟随全局设置。

窗口只通过 `App` 读取剧情目录和状态。剧情控制页按章节列出主线和羁绊，可以开启下一段，或跳转后播放。存档编辑使用草稿，应用前会先验证并备份；真实状态在草稿期间发生变化时，旧草稿不能覆盖。备份页显示实际存档路径、只读数据和按时间排列的备份。重置只清空剧情，不重置教程。

布局采用可编辑场景节点：紧凑的横向摘要、带章节筛选的分层剧情行、分为数值／完成记录／标记的编辑页，以及固定的保存操作栏。备份列表与存档原文分开展示，窄窗口通过换行和纵向滚动适配。布局说明及实际渲染证据见 [剧情测试台](story_test_bench.md)。

测试发起的播放沿用剧情弹窗，并显示「停止测试」。停止不把当前这段记为完成。剧本里的退出游戏在测试中改为停止并说明原因，正常游玩仍会退出。

完成记录使用「章节/剧情」。旧档里的短标识在迁移前先备份，重名时归到最早的章节，无法识别的记录原样保留。

## 验证方式

tests/unit/test_desktop_window.gd 使用真实场景检查窗口矩形、八向缩放、最小化保留内容与按钮锁定。

tests/desktop/verify_desktop.tscn 必须在 application/config/name 为 KnowledgeAdminDesktopVerification 的隔离工程运行；不会使用正式玩家的数据库和存档。它注入真实鼠标事件，检查启动、导航、AI 结果导入、JSON 文件导入、学习评分、剧情与帮助，并输出 desktop_review/verification.json 和 GPU 截图。

截图矩阵覆盖 1280×720、1920×1080 以及 80%、100%、150% 字号。AI 验收使用预设生成结果经过真实导入入口，不向外部模型服务发送请求。


剧情测试台的 GUT 在 Godot 4.7.2 下 13 项、79 个断言通过，覆盖跨章完成记录、旧档迁移、羁绊前置、跳转重排、存档往返、备份恢复、保存失败和编辑冲突。隔离工程 `tests/desktop/verify_story_test.tscn` 另有 56 项检查通过，包含连续触发、自然结束、选项等待时停止、延迟回调、测试退出、桌面焦点和学习界面恢复，以及 1280×720、1920×1080 下 100% 和 150% 字号的真实渲染。

## 验收记录

Godot 4.7.2：30 项 GUT 测试通过；真实 GPU 验收覆盖开机、八向鼠标缩放、菜单、两种导入、学习评分、剧情选项、弹窗恢复和六组分辨率／字号组合。报告及总览截图保存在 desktop_review 目录。未调用外部模型接口。

任务栏图标专项验收：运行 verify_desktop.tscn 时追加 `-- --taskbar-icons-only`，检查六组分辨率与字号组合下的方形比例、图标、名称提示和点击状态切换。118 项检查通过；预览与报告为 desktop_review/taskbar_icons.png 和 taskbar_icons_verification.json。
